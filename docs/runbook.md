## 알려진 이슈

- **타입체크 기존 에러 5건 — 이번 작업과 무관, 나중에 정리.** `npm run typecheck`가 5건 실패한다: `app/common/components/ui/box-reveal.tsx`(JSX 네임스페이스 미해결), `app/common/components/ui/icon-cloud.tsx`(인자 개수), `projects/wemembers-scheduler/src/components/{TaskCard,TitleLine,Tooltip}.tsx`(`verbatimModuleSyntax`에서 타입 전용 import 필요 3건). 전부 2026-08-01 포지셔닝 개편 이전부터 있던 것이고 개편이 건드린 파일과 겹치지 않는다. `npm run build`와 Pages 배포는 정상 통과하므로 배포를 막지는 않는다.

## 변경 이력

### 2026-10-20 (4차) — /publisher 구성 정리, 29건 문구 삭제

사용자 요청 세 건. 첫째, "운영팀 실요청 대표 29건 자동 검증 통과(가동 예정)"를 카드 두 곳(메인 개발 탭, 퍼블리셔 탭)과 docs/projects/cafe24-mall-operations.md에서 뺐다. 가동 전 수치라 근거가 약하다는 판단이다. Notion 페이지와 case-studies 저장소에는 아직 남아 있다. 둘째, 퍼블리셔 경로에서 카페24 자사몰 통합 운영 카드가 퍼블리싱 탭과 개발 탭에 겹쳐 보이던 것을 퍼블리싱 탭에만 두도록 개발 탭에서 걸러냈다. 메인(/)의 개발 탭은 그대로다. 셋째, About 하단 강조 블록을 props로 빼고, 퍼블리셔 경로에서는 케이스 스터디 대신 세모리포트 마크업 가이드(MARKUP GUIDE)를 보여준다. 퍼블리셔 검토자에게는 문서 저장소보다 가이드 실물 링크가 직접적인 근거라서다. 메인은 기본값이라 케이스 스터디 그대로다.


### 2026-10-20 (3차) — 링크패스, 위멤버스 성과문 구체화

두 카드의 성과문이 어느 프로젝트에나 붙는 한 줄이라 docs/projects와 데모 코드에서 확인된 사실로 다시 썼다. 링크패스는 믹스 차트와 도넛 차트, 정렬과 필터가 되는 w2ui 그리드, 센터와 확인, 토스트로 규격화한 팝업, 예외 화면 구축이고 기술에 w2ui를 더했다. 위멤버스는 props 기반 컴포넌트 분리, 전체 props 타입 명시, SCSS 리셋과 전역, 모듈 3계층이다. 카드 JSON, docs/projects 두 파일의 성과 절, Notion 두 페이지(결과물 앞에 성과 절 신설)에 같은 문장을 넣었다. Notion 링크패스의 기술 속성에는 w2ui 선택지가 없어 속성은 그대로 두었다(선택지 추가는 데이터소스 스키마 수정이 필요하고 목록을 통째로 덮어쓰므로 별도 작업). 위멤버스 Notion 결과물 링크는 끊긴 Netlify 주소에서 GitHub Pages 데모로 바꿨다. NH소상공인의 30% 수치는 사용자 결정으로 유지한다.


### 2026-10-20 (2차) — /publisher 히어로를 UI개발자 표기로, 데모 alt 전량 보수

사용자 요청으로 퍼블리셔 경로의 히어로를 "토끼처럼 빠르게 흡수하고 / 거북이처럼 묵묵히 일하는 / UI개발자 진승열입니다"로 바꿨다. 직함이 바뀌므로 페이지 제목과 og:title은 "UI개발자 포트폴리오", 설명문 첫 구는 "UI개발자 진승열의 포트폴리오", 키워드는 UI개발자 계열을 앞에 두고 퍼블리셔 계열은 유지했다. About 본문은 퍼블리싱이 하는 일 자체를 가리키므로 그대로다. Intro의 `subline`은 한 줄도 받도록 `string[]`로 바꿨고, 메인(/)은 기본값이라 변화 없다.

데모 alt는 남아 있던 412개를 전부 채워 0으로 만들었다. 고유 이미지가 34종뿐이라 파일명 기준 표로 일괄 적용했다. 원칙은 세 가지다. 옆에 같은 뜻의 텍스트가 있는 아이콘(응원, TOP 화살표, 목록 화살표, 지도 핀, 계좌와 카드, 로딩, 자리표시 썸네일)은 빈 alt, 의미를 전달하는 이미지는 짧은 명사(보고서 로고, 신규, 빼기, 같음), 버튼 안에 혼자 있는 이미지는 동작(닫기)이다. KT 장부비서 서브 페이지의 안내 이미지 두 장은 옆 문단 기준으로 설명을 썼다. 적용 스크립트는 세션 스크래치에만 있었고 저장소에는 결과만 남긴다.


### 2026-10-20 — 퍼블리셔 지원용 진입점 /publisher 신설 + 데모 접근성 보수

메인(/)은 AI 자동화 개발자 포지셔닝을 그대로 두고, 퍼블리셔 공고에 낼 때 쓰는 경로를 따로 만들었다. `app/common/page/publisher-page.tsx`가 같은 카드 데이터를 퍼블리셔 검토자 순서로 다시 배열한다. 제목은 "웹 퍼블리셔 포트폴리오", 히어로는 "탄탄한 코드 위에 감각적인 인터페이스를 그리는", About 첫 문장은 금융 화면 구현에서 시작해 13개 브랜드 자사몰 퍼블리싱과 운영을 혼자 맡는다는 결론이다. Skills는 `app/features/skiils/publisher-skills.ts`의 8장(HTML5, CSS3, JavaScript, jQuery, React, TypeScript, Claude Code, 배포와 운영)으로, 2026-07-17 최초 빌드(ec4b3e1)의 마크업 4장을 문체 기준에 맞춰 다시 썼다. Works는 퍼블리싱 탭이 기본이고, 카페24 자사몰 통합 운영 카드를 퍼블리셔 역할 문구(`app/data/project-data-publisher.json`)로 맨 앞에 더했다. 개발 탭은 메인과 같다.

이를 위해 Intro, About, Skills, Projects 컴포넌트에 선택 props(headline/subline, paragraphs, items, defaultTab/publishing/development)를 추가했다. 기본값은 기존 메인 문구 그대로라 메인 출력은 바뀌지 않는다. 프리렌더 목록과 sitemap, 배포 검증 목록에 `/publisher`를 넣었다. 지원서에는 퍼블리셔 공고면 `https://jinseungyeol.github.io/publisher`, 그 외는 루트를 적는다.

데모 보수: 퍼블리셔 검토자가 먼저 열어볼 KT 장부비서 PC 메인(img 37개)과 세모리포트 마크업 가이드(img 23개)에 alt를 채웠다. 장식 아이콘(화살표, 재생, 업종 아이콘, 응원 아이콘)은 빈 alt, 영상 썸네일과 후기 사진은 캡션 기반 설명이다. 데모 HTML 147개(세모장부 81, KT 앱 34, 위멤버스 30, 기타)의 `<html lang="en">`을 `ko`로 바꿨다. 위멤버스는 소스 `index.html`과 `dist` 양쪽을 고쳤고 배포 시 소스에서 다시 빌드된다. 나머지 데모의 alt 누락(약 430개)은 그대로다.

타입체크 기존 에러는 그대로이며 이번 변경 파일에서 새 에러는 없다.


### 2026-08-01 — 포지셔닝 개편 (퍼블리셔에서 AI 자동화 개발자로)

지원 직무(바이브 코딩 전문 개발자, AX 엔지니어)와 실제 Works가 어긋나 손해를 보던 포장을 맞췄다. 프론트엔드와 퍼블리싱 역량은 다른 직무 지원용이라 삭제하지 않고 순서만 내렸다. 메타와 About을 "AI 코딩 도구로 개발부터 배포와 운영까지 자동화하는 개발자"로 상향하고, keywords는 바이브코딩과 Claude Code, CI/CD 계열을 앞으로 옮겼다. Skills는 10카드를 8카드로 재편하면서 HTML5와 CSS3, JavaScript, jQuery를 한 블록으로 합치고 **배포와 운영 카드를 신설**했다. WebP 앱 성과에는 운영 9개 몰 확장과 엑박 사고 3계층 규명, 회귀 하네스, 실서빙 점검, 고아 작업 회수를 더했다. case-studies 저장소를 About 하단에 독립 블록으로 노출했고, 사이드 프로젝트는 틱택토를 빼고 캐러셀을 2단 그리드로 바꿨다. 버튼 라벨은 본업 카드가 "프로젝트 소개"와 "기술 문서", 사이드 카드가 "Demo"와 "소스 코드"다. 사이드의 GitHub는 문서가 아니라 소스 저장소라서 구분했다.

**사실 확인에서 걸러낸 것**: 크론은 Cloud Scheduler가 아니라 앱에 내장한 pg-boss였고, cafe24-perf 레포에는 워크플로가 없어 GitHub Actions를 그 카드 기술스택에 넣지 않았다. 운영 몰 수는 6이 아니라 9(스니펫 온보딩과 promote 완료가 현재 일치)로 재확인했다. 실물로 확인되지 않는 항목은 낮춰 쓰거나 뺐다.

**문체 기준**: 중점(가운뎃점)으로 단어를 붙여 쓰지 않는다. 나열은 쉼표로, 나머지는 문장으로 푼다. 카드 본문은 불릿 나열 대신 산문으로 쓰고 다른 카드와 길이를 맞춘다. 개수를 세어 앞세우는 표현("스킬 13개", "recipe 59건" 등)은 쓰지 않는다.

GA4는 `MoveLink` 컴포넌트의 onClick과 props로 발화하므로 DOM 변경에 영향받지 않는다. 다만 라벨 변경으로 `button_label`과 `link_text` 값이 바뀌었고 `link_url`은 그대로이므로, **배포 전후 비교는 `link_url` 기준**으로 해야 연속성이 유지된다.
